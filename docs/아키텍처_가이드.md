# 아키텍처 가이드 — 폴더 구조와 사용 기술 (초보자용)

## 1. 웹 서비스의 3층 구조 (기본 개념)

모든 웹 서비스는 크게 3층으로 나뉜다:

```
[프론트엔드]  사용자 눈에 보이는 화면. 버튼, 글씨, 지도.
      ↓ 요청 (예: "택시 불러줘")
[백엔드]     화면 뒤에서 일하는 서버. 규칙 검사, 권한 확인.
      ↓ 저장/조회
[데이터]     기록 보관소. 호출 내역 등이 여기 남는다.
```

## 2. 이 프로젝트의 폴더 = 역할

```
familiy-taxi/
├── src/
│   ├── app/          ★ 화면과 API의 "주소"가 되는 곳 (Next.js 규칙상 위치 고정)
│   │   ├── page.tsx        홈 화면          → 주소: /
│   │   ├── pickup/         출발지 확인 화면  → 주소: /pickup
│   │   ├── call/           호출 중 화면      → 주소: /call
│   │   ├── riding/         이동 중 화면      → 주소: /riding
│   │   ├── search/         목적지 검색 화면  → 주소: /search
│   │   ├── settings/       설정 화면         → 주소: /settings
│   │   ├── operator/       운영자 데스크     → 주소: /operator
│   │   ├── driver/         기사님 화면       → 주소: /driver
│   │   └── api/            ★ 백엔드 입구 (화면 없음, 데이터만 주고받음)
│   │       └── rides/          호출 API → 주소: /api/rides
│   ├── frontend/     화면(브라우저)에서 쓰는 코드 — store.ts (목적지 목록, 가족 연락처 등)
│   ├── backend/      서버에서만 도는 코드 — rides.ts (호출 저장·상태 변경·권한 로직)
│   └── shared/       양쪽이 함께 쓰는 "용어 정의" — ride-types.ts (호출이란 무엇인가, 상태 종류)
├── .env.local        비밀 설정 (DB 접속 주소 등) — git에 안 올라감
├── data/             (구) JSON 파일 저장소 — PostgreSQL 전환으로 더 이상 사용 안 함
├── docs/             사업 문서 (카카오 제안, 계획서)
├── public/           이미지 등 그대로 내보내는 파일
└── package.json      이 프로젝트가 쓰는 재료(라이브러리) 목록
```

## 3. 역할별 사용 기술

| 역할                     | 기술                                      | 무엇을 하는가                                                                                             |
| ------------------------ | ----------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| 화면 그리기 (프론트엔드) | **React**                                 | 버튼·글씨 등 화면 부품을 조립하는 도구. 화면이 데이터에 따라 자동으로 바뀜                                |
| 화면 꾸미기              | **Tailwind CSS**                          | 색·크기·여백을 코드에 바로 적는 스타일 도구 (큰 글씨 UI가 이걸로 구현됨)                                  |
| 프론트+백엔드 뼈대       | **Next.js**                               | React 위에 얹는 종합 틀. 주소(라우팅)·서버·빌드를 한 번에 담당                                            |
| 코드 언어                | **TypeScript**                            | 자바스크립트에 "타입 검사"를 더한 언어. 실수(오타, 잘못된 데이터)를 실행 전에 잡아줌                      |
| 백엔드 창구              | **Next.js Route Handler** (`/api/rides`)  | 화면이 보내는 요청(호출 생성, 배차 입력)을 받아 처리하는 REST API                                         |
| 데이터 저장              | **PostgreSQL** (접속 주소는 `.env.local`) | 표 형태의 정식 데이터베이스. 지금은 내 컴퓨터의 Postgres, 배포 시 Supabase/Neon 주소로 바꾸면 그대로 동작 |
| 권한/보안                | 운영자 키 (환경변수 `OPERATOR_KEY`)       | 배차 입력은 운영자만, 어르신은 자기 호출만 — 백엔드에서 검사                                              |
| (예정) 지도·로드뷰       | **카카오맵 JS SDK + 카카오 로컬 API**     | 출발지 AI: GPS → 건물 선정 → 로드뷰 사진 (프로젝트계획서 참고)                                            |

## 4. 예시로 보는 흐름 — 어르신이 택시를 부르면

```
① [프론트] 홈 화면(src/app/page.tsx)에서 "병원" 버튼 누름
② [프론트] 출발지 화면(src/app/pickup/page.tsx)에서 위치 확인
③ [프론트→백엔드] "호출해줘" 요청을 /api/rides 로 전송
④ [백엔드] src/app/api/rides/route.ts 가 받아서 → src/backend/rides.ts 가 검사·생성
⑤ [데이터] PostgreSQL의 rides 표에 호출 기록 저장 (상태: 호출 대기)
⑥ [프론트] 운영자 데스크(/operator)가 3초마다 백엔드에 "새 호출 있어?" 확인 → 배차 입력
⑦ [프론트] 어르신 호출 화면(/call)도 계속 확인 → "배차 완료! 12가3456 김기사님" 표시
```

이때 ①②⑥⑦은 프론트엔드, ④는 백엔드, ⑤는 데이터 층. **어르신 화면은 백엔드가 수동(운영자)이든 자동(배차망 연동)이든 똑같이 작동한다** — 이게 우리의 "2층 분리" 원칙이다.
