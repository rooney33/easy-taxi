## 1. 사업의 필요성 — 왜 이 문제인가

- 65세 이상 1,000만 명(20.3%), 2024년 12월 초고령사회 진입. 70대+ 스마트폰 보유율 73%, 그러나 75세+ 생활편의앱 이용률은 16.4%.
- 60대+ 택시앱(5회 이상) 이용률 35% — 20대(53.8%)의 2/3 수준. 약 절반이 아직 길에서 손을 들어 잡는다.
- **고령자가 택시앱에서 가장 배우고 싶은 것 1순위 = 출발지 설정법(52.3%, 한국소비자원).** 지도에서 핀을 정밀하게 옮기는 조작이 고령자에게 가장 어렵다.
- 출발지를 대충 잡으면: 기사가 못 찾음 → 전화가 옴 → 어르신이 설명을 못 함 → 호출 취소 → "다시는 안 쓴다". 첫 실패 경험이 이탈로 직결되는 구조.
- 기존 해법의 한계: 콜센터 대리호출(동행 온다콜택시 등)은 **의존을 유발**하고 어르신의 디지털 자립을 막는다. 우리 원칙은 "어르신이 앱에서 스스로 호출" — 그러려면 출발지 문제를 기술로 풀어야 한다.

## 2. 수익성 — 어떻게 돈이 되는가

1. **B2G 우선 (초기)**: 지자체 교통복지·디지털 포용 예산. 예비창업패키지 → 지자체 실증사업 수주. 출발지 AI는 "고령자 디지털 격차 해소 기술"로 정부 과제 적합성이 높음.
2. **배차망 제휴 (중기)**: 호출 실적 확보 후 티머니 온다 등과 제휴 — 콜당 중개 수수료. (온다는 티맵·서울시·디디추싱 등 외부 앱 호출 전례 3건 확인됨.)
3. **기술 라이선스 (장기)**: "출발지 AI" 모듈 자체를 기존 택시앱·배달앱·병원 이송 서비스에 SDK/API로 공급. 출발지 확정 문제는 고령자만의 문제가 아니라 모든 위치 기반 서비스의 공통 난제(특히 GPS 오차 큰 도심).

- 보수적 추정(기존 산식 유지): 70세+ 670만 × 스마트폰 73% × 타깃 30% × 활성 10% ≈ 14.7만 명 × 월 4회 × 콜당 3,000원 ≈ **연 212억 시장** (전국 확산 가정, 제휴 시 분배 전 기준).

## 3. 핵심 기능 — "출발지 AI" 상세 설계

### 3.1 사용자 경험 (어르신 시점)

1. 목적지 버튼(우리 집/병원/경로당)을 누른다.
2. 앱이 자동으로 위치를 잡는다 — 어르신은 아무것도 안 한다.
3. 화면에 **근처 큰 건물의 로드뷰 사진 1장**이 크게 뜬다: "**국민은행 앞으로 가서 서 계세요**" + [여기 알아요 / 모르는 곳이에요] 두 버튼뿐.
4. "여기 알아요" → 호출 완료. 택시는 그 건물 앞으로 온다.
5. "모르는 곳이에요" → 다음 후보 건물 사진 제시 (최대 2~3회) → 그래도 안 되면 운영자 연결(예외 처리).

원칙(기존 UX 원칙 계승): 화면당 정보 1개, 큰 글씨, 이모지 금지, 건물은 1개만, 선택은 예/아니오.

### 3.2 기술 파이프라인 (5단계)

```
① GPS 수집 → ② 위치 보정 → ③ 기준 건물 선정 → ④ 로드뷰 장면 생성 → ⑤ 승차 지점 확정
```

**① GPS 수집** — 브라우저 Geolocation API `watchPosition`으로 다중 샘플 수집(단발 측정보다 정확). `accuracy` 값으로 신뢰도 판단.

**② 위치 보정** — 도심 GPS 오차 10~50m 전제. 카카오 로컬 API `coord2address`로 도로명주소 획득, 도로 스냅(가장 가까운 로드뷰 파노라마 지점으로 스냅하면 자연스럽게 도로변으로 보정됨).

**③ 기준 건물 선정 (여기가 "AI")** — 카카오 로컬 API 카테고리 검색(반경 100~150m): 은행(BK9)·편의점(CS2)·약국(PM9)·주유소(OL7)·대형마트(MT1) 등 **어르신이 아는 프랜차이즈/랜드마크 우선**. 점수화: 거리(가까움) + 인지도(카테고리 가중치) + 로드뷰 촬영 존재 여부 + 도로변 여부 → 1등 건물 선택. 초기엔 규칙 기반 점수로 충분, 이후 "모르는 곳이에요" 응답 데이터를 학습해 가중치 개선(이 데이터 축적 자체가 해자).

**④ 로드뷰 장면 생성** — 카카오맵 JS SDK `kakao.maps.RoadviewClient.getNearestPanoId(건물좌표, 반경)` → `Roadview` 뷰어에 파노라마 로드. **핵심 계산: 파노라마 촬영 지점 좌표 → 건물 좌표의 방위각(bearing)을 구해 `viewpoint.pan`으로 설정** → 화면이 정확히 그 건물을 바라봄. 어르신에게는 조작 불가능한(잠근) 사진 1장처럼 보여줌.

**⑤ 승차 지점 확정** — "여기 알아요" 시 건물 좌표+건물명("국민은행 역삼점 앞")을 호출 정보에 저장 → 운영자/기사에게 전달. 기사용으로는 동일 로드뷰 링크 제공(기사도 픽업 지점을 사진으로 봄).

### 3.3 기술 스택

- 프론트: Next.js(현행 유지) + 카카오맵 JS SDK (지도·로드뷰·RoadviewClient)
- 지오코딩/POI: 카카오 로컬 REST API (coord2address, 카테고리/키워드 검색)
- 백엔드: 현행 호출 API(`/api/rides`) 구조 계승, 승차지점 필드(좌표·건물명·파노ID·pan값) 추가
- 비용: 카카오맵/로컬 API 무료 쿼터(일 30만 건 수준)로 베타 단계 비용 0원

## 6. 현 단계 실행 — 베타 설문조사 계획

**목적: "평상시 출발지 설정에 불편을 느끼는가"를 검증하고, 불편을 느끼던 사람이 출발지 AI로 불편을 느끼지 않게 되는지 확인한다.** (기능 완성도 평가가 아님)

- 대상: 실증 지역 복지관·경로당 70세+ 20~30명 (스마트폰 보유자)
- 방식: 사전 설문 → 출발지 AI 사용 → 사후 설문 (대면 보조, 문항 낭독)

**사전 설문 (불편의 존재 검증)**

1. 택시를 부를 때 "내가 어디 있는지" 말하거나 정하는 게 어려웠던 적이 있습니까? (자주/가끔/없다)
2. 택시앱에서 지도의 핀을 옮겨본 적이 있습니까? 그때 어땠습니까?
3. 기사님이 나를 못 찾아 전화 온 적이 있습니까?
4. 그 어려움 때문에 택시 부르기를 포기한 적이 있습니까?

**사후 설문 (해소 검증)** 5. 사진 속 건물이 어디인지 바로 알아보셨습니까? (바로/한참 보고/못 알아봄) 6. 그 건물 앞까지 혼자 가실 수 있겠습니까? 7. 이 방식이면 혼자서 택시를 부르실 수 있겠습니까? 8. (관찰 기록) 첫 제시 건물 인지 성공률 / "모르는 곳" 응답 횟수 / 소요 시간

**성공 기준(안)**: 사전 "불편 있다" 응답자 중 사후 7번 "예" ≥ 70%, 첫 건물 인지 성공률 ≥ 60%.

## 7. 성공 지표 요약

- 단기: 설문 성공 기준 달성 → 예비창업패키지 지원서의 실증 근거로 사용
- 중기: 실증 지역 호출 성공률(배차 후 기사-승객 접선 실패율 < 5%)
- 장기: 호출 실적 → 배차망 제휴 협상 카드
